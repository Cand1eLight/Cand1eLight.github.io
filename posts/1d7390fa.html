量子-机器学习QCNN代码复现

发表于2026-03-16|更新于2026-03-17

从零跑通 QCNN 图像分类：混合量子神经网络复现踩坑全纪录

💡 前言：万事开头难的 Baseline

我的毕业论文方向是“基于混合量子-经典神经网络的图像分类算法研究”。理论看了不少，但真要上手把前沿的开源代码在自己的电脑上跑通，才发现“工程实现”和“理论推导”之间隔着一整个太平洋的 Bug。

这篇博客完整记录了我基于 Python 3.8，在纯 CPU 环境下从零搭建环境、排查报错，并最终在 MNIST 数据集上用 8 个量子比特（PCA降维 + U_SU4 架构）跑出 97.96% 准确率的全过程。希望能帮到同样在量子机器学习（QML）泥坑里挣扎的同学们。

🛑 踩坑一：消失的“幽灵环境”（PowerShell 陷阱）

复现代码的第一步永远是配置虚拟环境，但我在这里结结实实地踩了 Windows 的一个暗坑。我一开始图方便，直接在 PyCharm 底部的 Terminal 终端里用 conda create 和 pip install，结果代码一跑就报：

ModuleNotFoundError: No module named 'numpy'

  • 🔍 排查原因：
    仔细看 PyCharm 终端的前缀带有 PS（PowerShell）。Windows 默认的 PowerShell 会拦截 Conda 的环境切换命令！虽然我输入了 conda activate，但底层根本没切过去，包全装到了全局环境里，导致我的专属环境成了无法调用的“幽灵”。
  • ✅ 终极解法：
    放弃 IDE 底层的终端，直接打开 Windows 菜单里正宗的黑框框 Anaconda Prompt (anaconda3)。

🌐 踩坑二：网络玄学与 SSL 证书拦截

环境建好了，准备一口气装完所有深度学习依赖包。结果清华源给我甩了一满屏的红字报错：

SSLError(SSLZeroReturnError(6, 'TLS/SSL connection has been closed (EOF)'))

  • 🔍 排查原因：
    因为电脑后台可能挂着网络代理工具，Anaconda Prompt 对网络安全证书的校验极其严格。它发现流量被劫持后，出于保护机制直接切断了清华源的 HTTPS 下载请求。
  • ✅ 终极解法：
    两步走：首先在终端里断开代理干扰，然后使用阿里云的纯 HTTP 镜像源，并附上免死金牌 --trusted-host 强行信任。

看到一排排 Successfully installed，爽感拉满。

💥 踩坑三：致命的版本代沟（TypeError 崩溃）

在 PyCharm 里绑定好环境后，满心欢喜地点击 Run，结果代码在加载量子库时当场暴毙，抛出一个极其底层的语法错误：

TypeError: 'type' object is not subscriptable

  • 🔍 排查原因：
    这是典型的版本代沟问题。pip install pennylane 默认下载了最新版（比如 0.37.0+）。但最新版的 PennyLane 底层源码使用了 Python 3.9+ 才支持的新式类型提示（如 tuple[list...]）。而我为了兼容老版本的深度学习框架，使用的是极为经典的 Python 3.8，它读不懂这种“超前”语法。
  • ✅ 终极解法：直接降级，对症下药！
    无需重装 Python，只需要把 PennyLane 回退到完美兼容 Python 3.8 的最后一个黄金大版本（0.31.0）：

系统非常聪明地连带卸载了冲突的底层包，并换上了完美兼容的 scipy 和 autograd。至此，环境彻底打通！

📌 总结

做工程复现，往往 80% 的精力花在配环境和解 Bug 上，20% 的时间在跑模型。但正是这些踩过的坑，补全了我们在学校课堂里学不到的工程鲁棒性思维。
