D2L 学习日志：从 Module 到 GPU：PyTorch 工程基础

发表于2026-08-15|更新于2026-08-20|Deep Learning
|浏览量:

今日状态

D2L 第 5 章第一遍完成。当天的重点不是某个新模型，而是理解 PyTorch 如何把模型变成可组织、可保存、可迁移的对象。

一、Module 是统一的组件抽象

当天曾把 Module 直觉化成“多个 MLP 的组合”，后来改成更准确的版本：nn.Module 可以表示一层、一个 block，也可以表示整个模型。

Sequential 只是按顺序串联模块；forward 才定义数据经过模型时的计算路径。

二、参数管理：注册比“变量存在”更重要

模型参数通常是 nn.Parameter。只有被模块正确注册，PyTorch 才能通过 net.parameters() 找到它们，并交给优化器更新。

当天逐项区分了：

对象 含义
weight / bias 某层的可学习参数
.grad 当前反向传播得到的梯度
state_dict() 参数与持久化状态的字典
named_parameters() 带名称遍历参数
net.parameters() 递归找到子模块中的已注册参数

初始化的目的，是让信号与梯度在网络中更容易稳定传播；Xavier 只是其中一种方法，不等于“初始化”这个概念本身。

共享参数时，同一个参数参与多处计算，反向传播会把各处贡献累加到同一个 .grad 中。

三、延迟初始化：按 shape 推断，不看数值

某些层在第一次接收输入前还不知道输入特征数，第一次前向时才根据输入 shape 创建参数。判断它需要什么参数的是维度结构，而不是输入里的具体数值。

当天还确认：教材页面出现的某些 D2L 代码与本地 PyTorch API 不完全一致，这是资料版本差异，不是漏学。
