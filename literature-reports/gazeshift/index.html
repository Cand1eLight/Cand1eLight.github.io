GazeShift：方法、结果与适用边界

精读 GazeShift 的任务设定、双编码器与注意力重建方法，并核对 VRGaze、校准协议、核心指标和部署结论的适用边界。

一句话概括

GazeShift 不直接用 gaze 标签训练视线编码器，而是让模型完成一个“把 source 眼图变成 target 眼图”的重建任务，并要求 target gaze embedding 为这次变化提供条件。论文再用少量带标签的注视点，把学到的 embedding 映射为视线角度。因此，更准确的概括是：无 gaze 标签的表征预训练 + 少样本校准，而不是“全流程不需要标签”。

研究问题：VR 眼动数据的几何条件不一样

许多远程眼动数据集使用桌面或正视相机；VR 头显中的近眼红外相机通常偏轴安装，眼睛在图像中的透视、遮挡和外观变化都不同。论文提出 VRGaze 数据集，包含 68 位参与者的 210 万张近眼红外图像，目标是补足这类偏轴采集数据的缺口。数据在受控头显与屏幕目标任务中采集，论文按参与者划分训练与验证数据。

这不是“样本越多，泛化就自然越好”的简单故事。论文的关键前提是：同一只眼在不同时刻的图像变化中，gaze 变化应当是重要因素。近眼相机减少了许多外部背景变化，但光照、瞳孔变化、头显滑移和裁剪偏移仍可能成为混杂因素。数据集规模解决了样本稀缺的一部分，并不能自动消除这些采集偏差。

方法：用重建任务迫使表征携带 gaze 信息

训练时，模型从 source 帧提取空间外观特征，从 target 帧提取 gaze embedding。外观编码器保留图像的二维结构；gaze 编码器生成紧凑向量。随后，模型通过自注意力和 gaze 条件化的交叉注意力调制 source 特征，再由解码器重建 target 图像。

直觉是：如果重建目标与 source 的主要差异确实来自视线方向，那么只观察 target gaze embedding 的分支，就必须编码足够的 gaze 线索，才能帮助模型完成“把 source 的视线转到 target 视线”的任务。推理时不再需要外观编码器、注意力重建模块或解码器；系统保留 gaze encoder，并接上轻量校准器。

论文还将模型自身的注意力图转成重建损失的软权重：高权重区域的重建误差对训练影响更大。公式中的 $\gamma$ 控制注意力分布的尖锐程度：$\gamma=1$ 是按注意力加权，$\gamma>1$ 会更集中，$0<\gamma<1$ 则更分散。它是损失权重变换，不是把 attention 简单“乘以某个常数”。

这个目标也有明确风险：如果 source 和 target 太相似，解码器可能直接复制 appearance，绕过 gaze embedding；如果二者间隔太久，光照、姿态或佩戴位置变化又会混入训练信号。因此，成对样本的选择不是单纯的数据加载细节，而是在规定模型要把什么变化解释为 gaze。

结果：数字必须和校准协议一起读

在 VRGaze 上，论文报告的 per-person 校准平均角误差为 1.84°；对照包括无监督 Cross-Encoder 的 2.15°、VAE 的 5.30°，以及监督 appearance-based 基线的 1.54°。所以这组结果支持“该无监督预训练表征配合个体校准后表现有竞争力”，但并不支持“无监督方法全面超过监督方法”。

1.84° 不是零校准结果。per-person 协议为每位验证参与者使用 $K\in{17,30,40,50,60}$ 个带标签注视点拟合 ridge regressor，其余样本用于评估；论文对不同 K 和参与者做 10 次随机划分后汇总结果。另一个 person-agnostic 设置则把跨参与者的标注点汇总训练共享回归器：K=100 时 GazeShift 为 2.73°，Cross-Encoder 为 2.83°；K=200 时分别为 2.13° 和 2.26°。这里的 K 是校准标注样本数，不是 KNN 的邻居数。

MPIIGaze 的远程相机结果需要把两种协议分开读。Table 7 使用在 Columbia Gaze 上预训练的表征，并按被试留一评估；每折用训练被试的 100 个带标签 embedding 训练监督 MLP。该协议下，轻量版 GazeShift 为 8.00°，Cross-Encoder 为 8.32°；表中同时列出 GazeShift 约 1M 参数、2M FLOPs，对照为 11M 参数、75M FLOPs，因此论文在这里主张约 10× 参数量与 35× FLOPs 的下降。Table 8 则额外在 MPIIGaze 的每折 14 位训练被试上进行无监督微调，再对留出的被试采用 100-shot 评估；GazeShift 为 7.15°，Cross-Encoder 为 7.20°，表中支持的是约 10× 参数量差异，没有列出这一协议下的 FLOPs。因此，不应把 7.15° 与 35× FLOPs 优势写成同一组测量结果。论文另在原生 VR 头显 GPU 上报告 gaze encoder 约 5 ms 推理时间；它不包括或不能代表完整的图像采集、裁剪、数据搬运、显示更新与整机调度链路，也不能直接外推到手机、A55 或 MCU。上述实验协议与数值见论文第 5.2 节及 Tables 7–8。

我认为最值得带走的三点

1. 自监督的前提本身就是研究对象

“重建目标图像”听起来只是代理任务，但它只有在样本对的变化主要由 gaze 引起时，才会有效逼出 gaze 表征。要验证这个机制，不能只看重建 loss 或漂亮的 attention 可视化，还应比较 gaze 与外观扰动下 embedding 的变化，并做能够区分二者的对照实验。

2. 注意力图是证据线索，不是因果证明

模型关注虹膜、眼睑附近区域，与这些区域包含 gaze 线索的解释相符；但热图本身不足以证明模型预测因果地依赖这些区域。更有说服力的检验包括遮挡或替换区域、保持 gaze 改变对比度、保持外观改变 gaze，以及报告多随机种子与结果波动。

3. 部署结论应保留完整测量边界

“轻量”至少要继续拆成参数量、FLOPs、峰值内存、输入预处理、设备延迟和能耗。论文给出的 5 ms 是有价值的设备侧证据，但它回答的是特定硬件上的模型推理耗时，并非完整头显眼动管线的所有成本。若要迁移到资源受限平台，还需要目标设备 profile，而不是仅从参数量推算。

结论与后续可检验的问题

GazeShift 的贡献可以分成两部分：面向 VR 偏轴近眼采集的 VRGaze 数据集，以及将 gaze/appearance 分支分离、通过交叉注意力完成 gaze 条件化重建的表征学习方法。论文结果表明，该表征在给定校准协议下有竞争力，并展示了跨 VR 与远程眼动设置的实验；它没有因此证明任意头显、光照、佩戴状态或硬件上的鲁棒性。

对后续复现而言，我会优先做一个 gaze × contrast 的 2×2 对照：分别改变视线方向与局部对比度，测量 embedding cosine distance、角误差及关注区域变化。若对比度变化比 gaze 变化更强地驱动 embedding，就说明当前表征可能仍依赖外观捷径。与此同时，应把不同校准点数、被试划分、随机种子和完整推理计时口径明确记录，避免把一个平均误差或单设备耗时扩写成系统级结论。
